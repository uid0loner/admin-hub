log-reader

A log file answers questions nobody has time to ask it. Drop one here and get the short version: who tried to get in and whether it worked, what the scanners found, when the errors started, and which message repeats ten thousand times. It reads web server access logs and syslog-style logs. The file is read by your browser and never uploaded.

which logs, and where they are

LogWhereNotes
nginx access log/var/log/nginx/access.logThe default "combined" format. Older days are in access.log.1 and compressed files: zcat access.log.*.gz.
Apache access log/var/log/apache2/access.log or /var/log/httpd/access_logCommon and combined format, with or without the virtual host in front.
Logins on Debian and Ubuntu/var/log/auth.logSSH, sudo, account changes.
Logins on RHEL, Rocky, Alma/var/log/secureThe same content under another name.
System log/var/log/syslog or /var/log/messagesKernel, services, cron.
Systems with only the journaljournalctl --since "2 days ago" -o short > journal.txtFor SSH only: journalctl -u ssh -o short.
A NAS, a firewall, a routerExport from its web interfaceWorks if the lines look like syslog: date, host, program, message.

The page matches known patterns. It does not know your application, cannot tell an admin's typo from an attack, and sees only what this one file contains: an attacker who got in may have deleted the lines. Times are shown in UTC. Syslog lines without a year are assumed to be from the last twelve months. Addresses in logs are personal data in many jurisdictions: the analysis stays in your browser, but think before you paste results into a ticket.
