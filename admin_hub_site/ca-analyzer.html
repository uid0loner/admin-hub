ca-analyzer

Paste your Conditional Access policies and find out what they really enforce. Ten baseline protections are checked, the usual gaps are flagged (report-only, exclusions, trusted locations), and every policy is rewritten as one plain sentence. The JSON is parsed in your browser and never uploaded.

  • partialMFA for all users, all apps
  • report-onlyLegacy authentication blocked
  • missingDevice code flow blocked

SourceHow

One script for both analyzersGenerate it in the script generator: a read-only export of Conditional Access policies and sign-ins.
Graph ExplorerGET https://graph.microsoft.com/v1.0/identity/conditionalAccess/policies, then copy the response

The export contains object IDs of users and groups but no names, passwords or secrets. Groups and users therefore appear as counts ("3 groups"): this page cannot look up who is in them, which is exactly the part you should review by hand. The checks read the policy definitions only. They cannot see Security Defaults, per-user MFA, authentication method settings or whether your named locations are sensible, and they do not simulate a specific sign-in: for that, use the What If tool in the Entra admin center.
