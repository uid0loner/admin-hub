rolling it out

  1. Break-glass first. Two cloud-only Global Administrator accounts with long random passwords, stored offline, in one security group. Set an alert on every sign-in of these accounts.
  2. Create in report-only. Run the script. Nothing changes for users yet.
  3. Read the logs for a week. Entra, Sign-in logs, open a sign-in, tab Report-only. Look for Failure: those are the people and devices the policy would have blocked.
  4. Fix what you find. Register MFA methods, replace scripts that use a user password, enrol devices, add named exceptions.
  5. Switch on one policy at a time. Start with the block on legacy authentication and MFA for admins. Leave a day between policies so you know which one caused a call.
  6. Check the result. Export the policies and run them through the CA analyzer, and test single sign-ins in the simulator.

The policies follow the templates Microsoft publishes in the Entra admin center, with a break-glass exclusion added to each. Conditional Access needs Entra ID P1, the two risk policies need P2. This page cannot see your tenant: whether a policy fits depends on your users, devices and existing policies. Read more in Conditional Access explained and the Entra ID hardening checklist.
